## 1. 产品愿景与定位

### 1.1 愿景

构建一套开放、可治理、不绑定模型的 AI 多 Agent 游戏开发系统。它本身不是一个游戏，而是一条由 AI Agent 驱动的游戏研发流水线——让一个小团队以接近 3A 的品质标准，从市场调研、概念设计一路到场景搭建、玩法实现、测试发布的完整闭环，开发出高品质游戏。

### 1.2 产品定位

**产品本体**：一套运行在 UE 5.8 之上的 AI 多 Agent 开发系统。包含 20 个领域 Agent（覆盖市场调研、概念设计、关卡设计、场景生成、玩法编程、灯光、音频、UI、性能剖析、质检、打包全流程）、10 个自研 Toolset、一个编排层（Orchestrator）和一套安全治理体系。使用者通过自然语言或结构化指令驱动它，Agent 产出可复现、可版本管理、可回滚的构建脚本，最终由 UE 编译生成游戏资产。

**落地验证方式**：为避免空转，系统绑定一个"参考游戏"（见 §1.3）作为端到端的验证载体——用它来证明这套工具链真的能做出一个可玩的、高品质的游戏。参考游戏是手段，不是产品本身的收入来源。

**核心竞争力**：
- 自研 Toolset + 自研编排层（L2/L4），源码可控，模型不绑架
- 20 个 Agent 覆盖从市场调研到打包发布的完整工业管线
- 开放标准（MCP）驱动 UE，可平滑迁移 UE6
- 安全治理：文件沙箱、风险分级审批、Git 钩子、自动驾驶式回滚

### 1.3 参考游戏（验证载体）

一个用于验证工具链能力的参考游戏。它本身不是产品，而是展示"这套 Agent 系统能做出什么"的落地 Demo 和压力测试。参考游戏做得越完整、越接近 3A 品质，就越能证明工具链的价值——这也是后续对外展示和商业化的最佳样板。

| 维度 | 定稿 |
|---|---|
| 游戏品类 | 黑暗奇幻动作冒险（第三人称），融合轻量 RPG 成长要素 |
| 核心玩法 | 半开放线性关卡，探索→收集→解谜→战斗→成长 的循环。关卡由 PCG 程序化生成，关卡结构由 Level Designer Agent 设计 |
| 美术风格 | 风格化写实（Stylized Realism），PBR 管线，暗黑奇幻方向。色调偏冷、材质以风化石材/金属/苔藓为主，参考《战神》(2018) 和《地狱之刃》的视觉语言，但不过度追求照片级真实——降低 AI 资产生成的难度和成本 |
| 世界观 | 原创奇幻世界。一个曾经辉煌的文明被未知力量摧毁后，自然用几百年的时间 reclaim 了城市。玩家扮演一个探索者，在废墟中寻找真相。主题围绕"文明与自然的对抗"和"记忆的代价" |
| 游戏时长 | 主线 5–8 小时，3–4 个生物群系区域，每个区域 1–2 小时 |
| 对标作品 | 《战神》(2018) 的线性叙事节奏 + 《地狱之刃：塞娜的献祭》的沉浸氛围 + 《瘟疫传说：安魂曲》的团队规模参考 |

## 2. 目标用户

产品是 AI 多 Agent 开发系统，因此目标用户分两层：**系统的使用者**（直接客户）和**系统产物的受众**（参考游戏的玩家，用于验证工具链有效性）。

### 2.1 系统使用者（直接用户）

| 画像 | 描述 | 核心需求 |
|---|---|---|
| AI 技术专家（本项目决策者与首批使用者） | 编排 Agent、定制 Toolset、监控生成质量 | 高效可控的生产力、可治理的流程、可量化的产出 |
| 独立/小团队开发者 | 没有完整的美术、策划、程序团队，靠少数人做高品质游戏 | 用自然语言驱动完成场景、玩法、测试的自动化生成 |
| 未来扩展的开发者 | 基于本工具链开发其他 UE 项目的团队 | 可复用的通用管线、模型可替换、UE6 迁移平滑 |

### 2.2 参考游戏受众（验证工具链的间接对象）

参考游戏本身不是产品，但为了证明工具链有效，它的品质和可玩性必须过关，因此需要定义它的受众来定标准：

| 画像 | 描述 | 对验证工具链的意义 |
|---|---|---|
| 核心玩家 | 25–40 岁男性为主，PC 单机玩家，玩过《战神》《艾尔登法环》《巫师 3》 | 若这些挑剔的核心玩家认可参考游戏，说明工具链产出的品质达标 |
| 次要玩家 | 18–25 岁动作玩家 | 检验动作与战斗部分的质量 |

## 3. 产品范围

### 3.1 范围内

- **AI 多 Agent 开发系统（产品本体）**：L2 自研 Toolset（10 个）+ L3 领域 Agent（20 个）+ L4 编排层 + 安全治理，完整闭环
- **策略与研究组**：S1–S6，市场调研、竞品分析、玩法设计、商业推演、技术评估、创意方向，产出《游戏概念提案》
- **场景生成管线**：PCG 驱动的生物群系地形/植被/遗迹/交互物程序化生成
- **玩法代码生成**：Verse/C++ 交互逻辑、状态机、AI 行为
- **外部资产管线**：纹理/3D/音频生成 → 质检 → 导入 UE → Nanite 适配
- **自动化测试与评审**：PIE 自动化测试、截图比对、代码审查、评分回退循环
- **参考游戏（验证载体）**：1 个可玩关卡，用于端到端验证工具链的完整性与品质

### 3.2 范围外（当前版本）

- 参考游戏的商业化发行：不把参考游戏作为独立产品发布、定价
- 多人联网：参考游戏仅单机，EOS 集成预留接口
- 完整叙事管线：参考游戏仅关卡级叙事片段，不做全篇剧情
- 工具链对外销售/授权：当前对内自用，商业化授权模式后续再定
- 移动端适配：不针对 iOS/Android
- 本地化：参考游戏仅中文，预留 i18n 框架

## 4. 功能需求

### 4.1 AI Agent 工具链系统

#### 4.1.1 MCP 工具平面（L2）

基于 UE 5.8 MCP + Toolset Registry，构建 10 个自研 Toolset，提供 Agent 可发现、可调用的结构化工具接口。所有 Tool 返回结构化 JSON，函数静态无状态，一个 Tool 一个职责，失败不抛异常。

| 子功能 | 职责 | 优先级 |
|---|---|---|
| F-TOOL-01.1 ProjectToolset | 命名规范校验、目录结构检查、资产审计 | P0 |
| F-TOOL-01.2 PCGToolset | 按 JSON 规格生成/修改 PCG 图、异步触发生成、读取结果 | P1 |
| F-TOOL-01.3 ArtPipelineToolset | 导入外部生成资产（纹理/网格/材质）、配置 Nanite、创建材质实例 | P1 |
| F-TOOL-01.4 BuildToolset | Live Coding 编译、全量编译、启动 PIE、自动化测试 | P1 |
| F-TOOL-01.5 SafeguardToolset | 文件沙箱边界检查、操作风险分级、审批门禁、Git 钩子 | P0 |
| F-TOOL-01.6 LightingToolset | 放置/调整光源、配置 PostProcess Volume、Lightmass 烘焙 | P1 |
| F-TOOL-01.7 AudioToolset | 放置环境音/音效、配置 Sound Cue/Attenuation | P2 |
| F-TOOL-01.8 UIToolset | 生成/修改 UMG Widget、绑定 DataTable、字体/颜色规范校验 | P2 |
| F-TOOL-01.9 DataToolset | CSV 导入、DataTable 资产创建、行数据校验 | P2 |
| F-TOOL-01.10 ProfilerToolset | 触发 GPU/CPU Profiler、解析 Unreal Insights 输出、生成超标报告 | P2 |

#### 4.1.2 安全与治理

UE MCP 没有认证、串行执行、Agent 可能改错关卡或重复创建对象。需要自建安全层：

| 子功能 | 说明 | 优先级 |
|---|---|---|
| F-TOOL-02.1 File Sandbox | `no_touch_zones`：`/Engine/` 和核心框架目录只读；Agent 仅写 `/Game/Generated/` | P0 |
| F-TOOL-02.2 Risk Gating | 三级审批：`read_only` 自动放行 / `mutating` 轻量审批 / `destructive` 强制人工确认 | P0 |
| F-TOOL-02.3 版本控制钩子 | Agent 每次改动后自动 commit + diff 报告，支持一键回滚 | P0 |
| F-TOOL-02.4 超时与隔离 | Tool 调用 30s 超时；disposable sandbox map 做初次验证 | P0 |

#### 4.1.3 领域智能体（L3）

20 个角色专精 Agent，覆盖从市场调研到打包发布的完整工业管线，通过 SharedState（结构化 JSON）通信。按阶段分为四组。

##### 策略与研究组（绿光阶段）

在确定游戏方向之前，先做足功课——市场分析、竞品研究、玩法概念验证、商业推演、技术可行性评估。这组 Agent 的输入是模糊的方向，输出是结构化的《游戏概念提案》，供人工审阅和选择。

| Agent | 核心能力 | 优先级 |
|---|---|---|
| S1 Market & Audience Analyst | 拉取市场数据（品类趋势/收入/用户画像）+ 市场规模估算 + 受众分析 | P1 |
| S2 Competitive Intelligence | 扫描竞品 → 生成竞品矩阵 + 特征对比 + 差异化机会分析 | P1 |
| S3 Game Design Strategist | 基于市场缺口提出 2–3 套核心玩法方案 + 机制设计 + 玩家体验模型 | P1 |
| S4 Business & Platform Strategist | 收入模型推演 + 平台策略 + 定价方案 + 18 个月盈亏预测 | P1 |
| S5 Technical Feasibility Analyst | 技术可行性评估 + 范围估算 + 关键风险识别 + 引擎能力匹配 | P1 |
| S6 Creative Direction Strategist | 世界观框架 + 叙事方向 + 视觉/音频策略 + 情绪板生成 | P1 |

提案由人工审阅后，选中的方向进入预生产——结构化数据直接注入 Director 的 GDD 流程。

##### 预生产组——在动任何资产之前，先确定做什么和长什么样：

| Agent | 核心能力 | 优先级 |
|---|---|---|
| ① Director | 解析用户意图 → 生成 GDD 结构化 JSON + 任务拆解 | P2 |
| ② Concept Artist | 生成风格指南 + 参考图 + 视觉规范（色调/材质语言/光照 mood） | P2 |
| ③ Level Designer | 生成 Blockout 规格（玩家动线/POI 坐标/空间分区/节奏曲线） | P1 |
| ④ Data Agent | 玩法数值规格 → CSV → DataTable 资产创建与校验 | P2 |

生产组——实际产出场景、玩法、资产：

| Agent | 核心能力 | 优先级 |
|---|---|---|
| ⑤ Asset Retriever | 检索 Fab/Quixel/本地库资产，返回结构化引用列表 | P1 |
| ⑥ Scene/PCG | 基于 Blockout + 风格指南生成 PCG 图 + 异步触发生成 + 截图验证 + 迭代优化 | P1 |
| ⑦ 3D Asset Generator | 在风格指南约束下调用外部 API 生成纹理/网格/材质 → 质检 → 导入 UE | P3 |
| ⑧ Lighting | 根据风格指南放置/调整光源 + PostProcess Volume + 截图验证氛围 | P1 |
| ⑨ Gameplay | 生成 Verse/C++ 玩法模块 + 编译 + 错误修复 | P2 |
| ⑩ Audio | 放置环境音 + SFX + 配置 Sound Cue/Attenuation | P2 |
| ⑪ UI | 生成 UMG Widget（HUD/交互提示/状态面板）+ 绑定 DataTable | P2 |

验证与交付组——全部产出进验证闭环：

| Agent | 核心能力 | 优先级 |
|---|---|---|
| ⑫ Profiler | 运行 GPU/CPU Profiler + 解析 Unreal Insights 输出 + 生成超标报告 | P2 |
| ⑬ Reviewer/QA | 代码审查 + 自动化测试 + PIE 截图比对 + 评分 + 缺陷报告 | P2 |
| ⑭ Build Agent | 通过评审后触发平台打包（UBT）+ 生成可执行包 | P3 |

Agent 间通信全部走 SharedState JSON Schema，不传自由文本。每条消息携带 `version`（semver）和 `parent_hash`（SHA-256）。Orchestrator 维护依赖 DAG，上游变更自动标记下游 stale，下游 diff 后决定是否重跑。传播深度限制在 3 层。多 Agent 并发写同一关卡时按坐标范围分区，共享区单独协调。

#### 4.1.4 编排层（L4）

技术选型推荐 LangGraph 或自研状态机，搭配 MCP Client。负责：

| 子功能 | 说明 | 优先级 |
|---|---|---|
| 任务编排 | 顺序 / 条件分支 / 循环回退（评分 < 70 或含 critical bug → 回退，最多 3 次） | P2 |
| 依赖 DAG 引擎 | 维护 Agent 间有向无环依赖图；上游变更自动标记下游 stale；传播深度 ≤ 3 层 | P2 |
| RAG Grounding | 检索 UE 官方文档 + 项目规范 + 引擎源码，注入 Agent 上下文 | P1 |
| 记忆分层 | 短期（对话）→ 工作记忆（SharedState）→ 长期（向量库，已验证代码索引） | P2 |
| 模型路由 | 简单任务用小模型（Haiku/Flash）、复杂任务用大模型（Opus/Pro）；模型可替换 | P2 |
| 人工卡点 | 不可逆操作（构建/发布）强制人工审批；生成资产入库前人工过审 | P0 |

### 4.2 参考游戏项目

#### PCG 场景生成

AI 驱动的程序化场景，覆盖至少 3 种生物群系。

| 子功能 | 说明 | 优先级 |
|---|---|---|
| 生物群系 PCG 图 | 森林、废墟、山地 3 种群系的完整 PCG Graph | P1 |
| 地形生成 | 基于 spline 的地形层权重，驱动群系边界 | P1 |
| 植被分布 | Surface Sampler + 属性过滤 + Mesh Spawner，支持密度/坡度约束 | P1 |
| 交互物放置 | 可收集品、机关、敌人生成点按规则放置 | P1 |
| 动态调整 | Agent 根据截图反馈迭代参数 | P2 |

#### 核心玩法

支持探索、收集、解谜、战斗的玩法循环。

| 子功能 | 说明 | 优先级 |
|---|---|---|
| 角色控制 | 第三人称角色移动、跳跃、攀爬、交互 | P1 |
| 收集系统 | 可收集物品（符文石等），计数 + UI 反馈 | P1 |
| 机关解谜 | 触发器驱动的机关门、移动平台、压力板 | P1 |
| 战斗系统（轻量） | 近战攻击、闪避、敌人 AI（巡逻/追击/攻击） | P2 |
| 关卡状态机 | 关卡全局状态管理（未激活 → 进行中 → 完成） | P1 |

#### 资产管线

| 子功能 | 说明 | 优先级 |
|---|---|---|
| 外部模型生成 | 通过外部 API 生成纹理/3D 网格/材质 | P3 |
| 自动导入 | ArtPipelineToolset 自动导入 + Nanite 配置 | P3 |
| 资产元数据 | 每条资产写入 `SourceAssetMetadata`（来源/prompt/模型版本/license） | P3 |
| 质量审查 | 评测 Agent 检查：风格一致性、三角面数、内容安全 | P3 |

#### 关卡设计与 Blockout

在 PCG 场景生成之前，先完成灰盒关卡设计，确保空间布局和玩家动线合理。

| 子功能 | 说明 | 优先级 |
|---|---|---|
| 玩家动线 | 定义 spawn → POI → 高潮 → 出口的路径节点与节奏曲线 | P1 |
| 空间分区 | 按功能划分区域（探索区/解谜区/战斗区），分配坐标范围 | P1 |
| Blockout 放置 | 用简单几何体标记关键结构位置（门、平台、建筑遗迹） | P1 |
| 约束输出 | 生成 Blockout JSON → 传递给 Scene/PCG Agent 作为生成约束 | P1 |

#### 灯光与后处理

为 PCG 场景自动配置灯光和后期处理，达到风格指南定义的氛围。

| 子功能 | 说明 | 优先级 |
|---|---|---|
| 主光源 | 根据风格指南放置 Directional Light + Sky Light + Sky Atmosphere | P1 |
| 局部光源 | 在 POI 和路径节点放置点光源/聚光灯 | P1 |
| PostProcess | 配置 PostProcess Volume（色调映射/Bloom/Ambient Occlusion/曝光） | P1 |
| 氛围验证 | 截图回传 → 与风格指南参考图比对 → 迭代调整 | P2 |

#### 音频

为场景和玩法添加环境音和交互音效。

| 子功能 | 说明 | 优先级 |
|---|---|---|
| 环境音 | 按生物群系放置 Ambient Sound（风/水/鸟鸣/虫鸣） | P2 |
| 交互 SFX | 收集品拾取音效、机关门开合音效、脚步声表面切换 | P2 |
| 音频配置 | Sound Cue + Attenuation 设置（距离衰减/空间化） | P2 |

#### UI/HUD

为可玩 Demo 提供基本的用户界面。

| 子功能 | 说明 | 优先级 |
|---|---|---|
| HUD | 收集品计数、关卡进度指示器 | P2 |
| 交互提示 | 动态提示（"按 E 收集"、"需要 4 个符文石开门"） | P2 |

## 附录 A：产品决策记录

以下为 PRD v0.2 定稿过程中确认的关键决策及其依据。除第 1 项外，均为**参考游戏（验证载体）**的选型决策——参考游戏用于端到端验证工具链能力，其品类选择基于市场数据以确保验证结果有行业说服力。

| # | 事项 | 决策 | 依据 |
|---|---|---|---|
| 1 | 产品形态 | **AI 多 Agent 开发系统**（本体），参考游戏为其验证载体 | 多 Agent 系统是核心 IP（L2 Toolset + L4 编排层），参考游戏证明其产出能力 |
| 2 | 参考游戏品类 | 黑暗奇幻动作冒险（第三人称） | Steam 2025 年动作+RPG 占收入 ~75%；黑暗奇幻月收入超 1 亿美元 |
| 3 | 参考游戏目标平台 | PC 首发（Steam + EGS），主机 P3 评估 | PC 游戏市场连续多年创纪录增长；Steam 2025 年再创新高 |
| 4 | 团队规模 | 3–5 人核心 + AI Agent | 与 AI Agent 替代人力的目标一致；参考《瘟疫传说》等中小团队高品质先例 |
| 5 | 美术风格 | 风格化写实（Stylized Realism），PBR 管线 | 降低 AI 资产生成难度；避免照片级写实的高成本；Quixel Megascans 可直接用于材质基底 |
| 6 | 参考游戏时长 | 5–8 小时主线 | 小团队合理范围；AI 生成 3–4 个生物群系的可控 scope |
| 7 | 多人/联机 | 参考游戏不做多人 | 单机叙事是主要验证方向；EOS 预留接口供未来扩展 |
| 8 | 本地化 | 参考游戏首发中文 + 英文 | 覆盖 Steam 最大两个语言市场（中文 ~30%，英文 ~35%） |
| 9 | 对标作品 | 《战神》(2018)、《地狱之刃》、《瘟疫传说：安魂曲》 | 均为线性/半开放动作冒险，验证了品类的可行性作为工具链压力测试的合适载体 |
