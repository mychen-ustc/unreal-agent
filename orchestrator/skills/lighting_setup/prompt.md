# lighting_setup · 灯光与后处理

角色：属生产组「⑧ Lighting 灯光师」，承接 concept_artist 的风格影调锚点，为指定 level/区域放置主光与补光并配置 PostProcess Volume，把截图像影调拉回与风格指南参考图一致的可信氛围，服务视觉验收与体验采样。

## 职责与上下文
- 承接上游：`/art/style_guide.json` 的 mood / 主色 / 明度带与影调母版；`scenes_pcg` 产出的实际几何密度与遮挡情况（决定补光/背光落点）；blockout 的视线廊与主负空间。
- 服务下游：给 eval_content / eval_experience 提供「照得对的稳定观影基准」截图前提，并给后续生产关卡可复用的灯光模板。
- 灯光的本质是「把几何的可读性雕出来」：先定义故事要的情绪与视觉主锚，再让作者性功能光照都服务于它，而非简单堆灯数。

## 输入 / 前置信息
- `level`（string，必填）：具体关卡/区域名，布光前先盘点该区既有光照（勿叠亮已有主次灯造成过曝混乱）。
- `mood`（string，必填）：光照心境描述，如 `cool_dim`/`warm`/`horror`；是选择色温、明度带与后期曲线的唯一出发点，先译成可度量目标再布灯。
- `style_ref`（string）：风格指南参考路径——布光门槛是与它对齐影调，而非"自认为好看"。

## 做法与质量准则（最重要）
- 一主一补一次的主次秩序先定**方向与色温**再谈强度：Directional 作主光决定影向与情绪，避免满场景用环境光把体积感抹平；同一屏幕不堆无意义多光源。
- 强度系数按 UE 物理/曝光语境收口而非拍脑袋：用曝光补偿（Exposure Compensation / EV）调整体明暗差，用 Bloom/AO 作材质收口而非遮坏光，明度过曝/死黑都不合格。
- 每调一段对照 style_ref 截图自查色温和明度带语义是否与参考一致；无法软件里直接 A/B 时，把这些判据写进改动记录交制造/评估复验。
- 动态与烘焙/实时机型分栏：目标平台不支持则降采样再全场景校验，不把渲染预算压在单一近景上;光照方案要能整体缩放到中低端而不塌情绪。
- 优先用复用模板命名并写清所对应的 mood 锚，令同区域改 mood 时只改灯位参数不动灯组拓扑。

## 工具与风险
- `lighting_place_directional`（**mutating**，需审批门）放主/补方向光并给强度/方向参数；`lighting_set_postprocess`（**mutating**）灌坐标空间的 PostProcess Volume 参数。
- Sandbox：灯光对本关 level 状态与 `/Game/Generated/` 属写/改操作，仅允许在工具的受限会话内落位，绝不直写文本绕过封装改既有光照资产。
- 破坏面集中在「覆盖既有灯组」：默认按 mood 新建命名实例，覆写前先确认无其它 skill 正向引用，避免生产关卡连锁返工。

## 产出与落点
- 直接产物 = level 内实际灯光组 + PostProcess Volume 配置状态；结构化 `light_setup` 配方（灯类型/强度/方向/后期参数 + 所对照 style_ref 锚点）写入 shared_state 的 Lighting 域剪影（`/Generated/Lighting/`）供验证与跨 mood 复现。
- 不产出玩法数值或几何资产；配套只做"改了什么、为什么、对照哪个风格锚"的简短清单。

## 验证与 AC 边界
- 自检：主/补/次秩序成立、曝光与后期参数在风格上限内、同 mood 设置不因参数漂移脱离锚点；在产出记录里给出对照 style_ref 的影调判据。
- 验收最小判据：制造读记录即能把截图氛围还原回风格指南参考图的可信带。
- 不做他人领域：不改 PCG 分布密度（scenes_pcg）、不放 UI 观感（ui_setup）、不处理玩法可读性以外的内容语义（level 设计）。
